# Diff Hunk Review

[English](README.md) · **Русский**

Chrome-расширение для code review в GitHub и Bitbucket Cloud: просмотренный блок изменений скрывается одним кликом, как `stage hunk` в редакторе. В большом pull request'е видно только то, что ещё осталось посмотреть.

Скриншоты сняты в Bitbucket Cloud, в GitHub расширение выглядит так же.

## Зачем

- **Большой PR по частям.** Галочка **Viewed** в GitHub работает только для файла целиком. Здесь файл на 600 строк можно отмечать по одному hunk'у и вернуться к нему позже.
- **Ничего не теряется.** Прогресс сохраняется для каждого PR. Hunk, который изменился новым коммитом или переехал в другое место, сам показывается снова.
- **Видно, сколько сделано.** У каждого файла есть счётчик `2/5 hunks`, а popup считает, сколько вы просмотрели сегодня, за неделю, за месяц и за всё время.
- **Не мешает.** Не нужны вход и настройка. Расширение добавляет по маленькой кнопке на hunk, остальное в GitHub не меняется.

## Возможности

- **Hunk'и.** Hunk — это блок подряд идущих изменённых строк. Синие строки `@@` и неизменённый контекст не трогаются.
- **Отметка.** На первой строке каждого hunk'а висит плавающая кнопка **✓**: слева поверх номеров строк или справа (см. настройки). При наведении она показывает **Mark reviewed**. Клик сворачивает hunk в одну серую строку `✓ Reviewed −6 +3 · show`, кнопка в этой строке возвращает его обратно.
- **Построчно.** Выделите строки мышкой, даже внутри одного огромного hunk'а вроде нового файла, и рядом с выделением появится кнопка **Mark N lines reviewed**. Выделенные изменённые строки свернутся в одну серую строку со своей кнопкой **show**. Hunk считается просмотренным, когда отмечены все его строки, а его собственная кнопка отмечает только оставшиеся.
- **Липкая кнопка для длинных hunk'ов.** Когда первая строка hunk'а уходит под заголовок файла, кнопка едет следом прямо под заголовком, и hunk можно отметить, не прокручивая назад. Свёрнутая строка встаёт на место кнопки.
- **Прогресс по файлу.** Рядом с именем файла показывается счётчик, например `2/5 hunks`.
- **Сохранение для каждого PR.** Состояние переживает перезагрузку и синхронизируется между вкладками с одним PR.
- **Умное сравнение.** Каждая изменённая строка узнаётся по своему тексту и двум строкам с каждой стороны, а не по номерам строк:
  - правки в другом месте файла её не сбрасывают;
  - раскрытие контекста её не сбрасывает;
  - изменённая или перенесённая строка показывается снова вместе с ближайшими соседями.
- **Popup.** По клику на иконку на панели инструментов можно:
  - включить или выключить расширение;
  - выбрать положение кнопки (слева или справа);
  - включить или выключить автоматический Viewed;
  - посмотреть, сколько hunk'ов, строк и файлов просмотрено сегодня, за 7 и 30 дней и за всё время;
  - посмотреть столбчатый график за последние 30 дней по hunk'ам, строкам или файлам; при наведении на день видно его значение.
- **Сам ставит Viewed.** Когда вы отмечаете последние строки файла, расширение ставит галочку **Viewed** самого сайта (она есть и в GitHub, и в Bitbucket). Это происходит только при таком действии, поэтому если снять галочку вручную, она так и останется снятой. Это можно выключить в popup.
- **Viewed тоже считается.** Если поставить галочку **Viewed** самого сайта, в статистику добавляются файл и его hunk'и, ещё не отмеченные кнопкой. Если снять галочку, вычитается ровно то, что было добавлено.

## Безопасность и приватность

Расширение сделано так, чтобы ему было легко доверять и его было быстро проверить.

- **Код можно прочитать за один присест.** Около 1400 строк TypeScript в `src/`, разложенных по зонам ответственности (см. [Устройство](#устройство)).
- **Лёгкое.** Собранное расширение весит около 38 КБ, из них 23 КБ JavaScript. Внутри нет фреймворков и чужого минифицированного кода.
- **Нет runtime-зависимостей.** Раздел `dependencies` в `package.json` пуст. Всё из `devDependencies` нужно только для сборки, тестов и линтера и в `dist/` не попадает.
- **Нет сетевых запросов и телеметрии.** В коде нет `fetch`, `XMLHttpRequest`, WebSocket и удалённых скриптов. Расширение не обращается к API GitHub и Bitbucket и никуда ничего не отправляет.
- **Действует только через страницу.** Единственное, что расширение меняет на GitHub или Bitbucket, — галочка **Viewed**: оно нажимает её так же, как вы, после того как вы отметили последние строки файла.
- **Нет аккаунтов и токенов.** Оно не просит GitHub-токен или вход и не читает cookies. Оно работает только с тем, что уже есть на странице.
- **Одно разрешение.** `manifest.json` запрашивает только `storage`. Content script работает только на `https://github.com/*` и `https://bitbucket.org/*`. Нет фонового воркера, `host_permissions` и `web_accessible_resources`.
- **Аккуратная работа с DOM.** Текст пишется через `textContent`, никогда через `innerHTML`, ничего не выполняется через eval. Клики, сгенерированные скриптами страницы, игнорируются.
- **Данные остаются у вас:**
  - скрытые hunk'и и статистика хранятся в `chrome.storage.local` на этом устройстве; PR, которые не открывали 30 дней, удаляются;
  - только настройки (вкл/выкл, положение кнопки, автоматический Viewed) лежат в `chrome.storage.sync` и следуют за вашим профилем Chrome.
- **Защита от supply-chain атак** при разработке. См. [Разработка](#разработка).

## Установка

```bash
pnpm install
pnpm build
```

Затем откройте `chrome://extensions`, включите **Developer mode**, нажмите **Load unpacked** и выберите папку `dist/`.

## Требования и ограничения

- После обновления или перезагрузки расширения уже открытые вкладки показывают плашку с просьбой перезагрузить страницу: Chrome не отдаёт им новую версию до перезагрузки.
- На GitHub расширение работает только с новым React-интерфейсом «Files changed» (`/pull/N/changes`). Без входа в аккаунт GitHub показывает старый интерфейс, и там расширение ничего не делает.
- На Bitbucket расширение работает с pull request'ами Bitbucket Cloud (`bitbucket.org/<workspace>/<repo>/pull-requests/N`), со входом и без. Bitbucket Data Center не поддерживается.
- Split view на GitHub проверен только unit-тестами, на Bitbucket пока не поддерживается.
- Если отметить файл Viewed не кликом по галочке, а иначе, например горячей клавишей, это не попадёт в статистику.
- Ключи hunk'ов, изменённых последующими коммитами, остаются в storage, пока запись PR не устареет.

## Разработка

| Команда | Что делает |
| --- | --- |
| `pnpm dev` | пересобирает `dist/` при изменениях |
| `pnpm build` | собирает `dist/` |
| `pnpm typecheck` | проверяет типы |
| `pnpm test` | запускает unit-тесты (Vitest + jsdom) |
| `pnpm lint` | линтер и проверка форматирования (Biome) |
| `pnpm format` | исправляет замечания линтера и форматирование (Biome) |
| `pnpm icons` | рендерит `assets/icon.svg` в `public/icons/*.png` (нужен Inkscape) |

После пересборки нажмите кнопку обновления расширения на `chrome://extensions` и перезагрузите страницу PR.

- **Коммиты** пишутся по [Conventional Commits](https://www.conventionalcommits.org/ru/). commitlint проверяет их в хуке `commit-msg`, а хук `pre-commit` запускает Biome на застейдженных файлах. Оба хука ставит `pnpm install`.
- **Зависимости** ставятся через pnpm с защитой от supply-chain атак (`pnpm-workspace.yaml`):
  - только версии, опубликованные не меньше 7 дней назад;
  - установка падает, если у версии слабее подтверждение публикации, чем у предыдущих;
  - нет транзитивных зависимостей из git и tarball;
  - нет install-скриптов зависимостей;
  - реестр и версия pnpm закреплены.

## Устройство

| Файл | Назначение |
| --- | --- |
| `src/sites.ts` | всё, чем отличаются GitHub и Bitbucket: селекторы, строки, ключ PR, галочка Viewed |
| `src/content.ts` | точка входа: подключает `MutationObserver`, клики и события storage к контроллеру |
| `src/controller.ts` | логика страницы: текущий PR, загрузка и сохранение состояния, какие таблицы пересканировать |
| `src/review.ts` | применяет состояние к файлу: свёрнутые строки, кнопки, прогресс |
| `src/dom.ts` | селекторы GitHub и разбор таблицы диффа на hunk'и |
| `src/hunkKey.ts` | ключ строки: путь файла + хэш строки и её соседей с той же стороны |
| `src/selection.ts` | кнопка рядом с выделением текста |
| `src/storage.ts` | состояние PR в `chrome.storage.local` |
| `src/settings.ts` | настройки в `chrome.storage.sync` |
| `src/stats.ts` | дневные счётчики и сводка: сегодня / 7 дней / 30 дней / всё время |
| `src/popup.ts` | popup на панели инструментов |

Оба сайта рендерят дифф через React и подгружают файлы постепенно. Чтобы не мешать React, расширение не вставляет свои строки. Оно ставит атрибуты `data-ghr-*` на существующие строки и добавляет по одной кнопке на первую строку каждого hunk'а. После каждой перерисовки всё применяется заново, и повторный проход ничего не меняет.

Content script и popup собираются в отдельные IIFE-бандлы (`dist/content.js`, `dist/popup.js`) двумя проходами Vite, потому что content scripts в MV3 не поддерживают ES-модули. Манифест, CSS, `popup.html` и иконки лежат в `public/` и копируются как есть.

Если GitHub или Bitbucket поменяет разметку, смотрите `src/sites.ts`: там собраны все селекторы, зависящие от сайта.
